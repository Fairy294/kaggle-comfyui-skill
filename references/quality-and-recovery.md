# 验收、故障与恢复

## 区分执行状态与验收结果

| 状态 | 判断依据 |
| --- | --- |
| 已准备 | 本地任务目录和输入配置已生成 |
| 已提交 | 平台确认任务引用；仍可能排队或安装依赖 |
| 正在生成 | 实际 ComfyUI 事件、history 或采样日志；心跳不能证明采样前进 |
| 技术完成 | 任务 `result.json` 为 `COMPLETED`，输出文件完整且通过解码检查 |
| 验收通过 | 实际图像或视频满足用户约定的内容、质量和交付要求 |

平台 `COMPLETE` 只表示会话结束。下载到 `FAILED` 的任务结果时保留诊断，不能据此宣称生成成功。

## 下载与检查

1. 使用 `download --job JOB_DIR` 拉取终态任务目录，已有下载可用 `verify --job JOB_DIR` 重查。
2. 核对任务 UUID、工作流、挂载输入和输出清单。文件大小与 SHA256 以本任务清单为准，无需与历史任务产物比较。
3. 查看实际图像；视频使用 ffprobe 检查分辨率、帧率、帧数、时长和音轨，并执行完整解码，例如：

```sh
ffmpeg -v error -xerror -i FILE -f null -
```

解码命令成功退出且无错误后，再检查画面。查看视频帧总览并逐帧核查动作过渡、细节和接缝；按任务检查身份、服装、手脸、构图、黑边、重影及音画同步。锐度分数不能代替实际查看。

runner 的技术解码结果与本地下载完整性检查分别保留。哈希吻合不能代替内容验收，`visual_accepted` 不会因下载校验通过而自动变为真。

## 本地导出与交付

在独立任务目录处理原始素材、原生帧和导出文件。导出使用临时文件和独占锁，完成解码、帧数及音频对齐检查后再原子改名，避免后台巡检与即时操作同时覆盖同一文件。

默认保留原始输出，不添加说明文字或水印，不通过光流或叠化掩盖缺陷。需要编辑或修复时按用户要求处理，并说明质量变化。交付实际文件；预览与最终成果在聊天中明确说明。

## 故障处理

| 故障 | 下一步 |
| --- | --- |
| 认证失败 | 停止联机操作，检查本机 `KAGGLE_API_TOKEN` 环境变量，不输出令牌 |
| 提交响应未知 | 保留 `SUBMISSION_UNKNOWN` 标记，按唯一任务引用查询远端，不重复提交 |
| 节点缺失或文件校验失败 | 检查节点版本、模型名称、真实挂载路径与预期校验值，修复后再判断是否需要新运行 |
| 显存或内存不足 | 核对 CUDA OOM、cgroup 事件、进程退出码与堆栈；SIGSEGV 本身不能证明 OOM |
| 工作进程异常 | 检查主进程及 worker 日志，确认实际失败阶段后处理版本或通信问题 |
| 解码失败 | 保留可用 latent、原生帧及诊断，优先检查解码或本地封装步骤 |
| 下载中断 | 保留部分下载并核查；已有完整文件先运行 `verify`，需要重下时将原下载另存，避免覆盖 |

每次重试都应有明确修复和授权范围；新的 GPU 运行先复核实时额度与时限。网络只读查询可有界重试，未知结果的写请求先核对远端状态。

取消使用 Kaggle 对应会话的 Stop Session，并确认远端终态。关闭巡检仅停止宿主检查；没有准确会话信息时报告尚未确认停止。
