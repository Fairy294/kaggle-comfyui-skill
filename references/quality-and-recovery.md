# 验收、故障与恢复

## 分离五种状态

1. 已准备：本地文件生成，无GPU。
2. 已提交：官方确认版本与唯一slug，不等于排队完成。
3. 正在生成：依据真实进程/ComfyUI history/事件；心跳证明观察器活着，不保证采样前进。
4. 技术完成：result=COMPLETED，文件存在、大小/hash吻合、图片有效或视频全解码。视觉验收仍False。
5. 画面通过：检查身份、动作、裙摆/服装、手脸、黑边、重影、文本/水印、音轨、时序/接缝及用户明确约束后再决定。不能用锐度分数代替逐帧检查。

## 下载后检查

`download` 从官方分页获取本task目录并核验清单；`verify` 重查。检查result身份/工作流SHA256、output-manifest身份、输出大小与SHA256。结果为FAILED时保留诊断，不误报“没有视频=下载漏了”。传输完整性不是第三方插件输出的独立安全证明。

图像查看实际画面；视频用ffprobe检查时长/分辨率/FPS/帧数/音轨，用`ffmpeg -v error -xerror -i FILE -f null -`全解码，输出空日志+退出0才算解码通过。检查所有原生帧contact与关键细节，特别动作过渡帧，不只选几张好看的帧。

## 本地导出纪律

在独立任务目录导出临时文件，使用独占锁；完成后严格全解码、帧数、音频对齐检查，再原子改名。宿主定时巡检与用户即时询问可能并发导出，不能同时覆盖一个mp4，重复moov/覆盖mdat会造成坏文件。原始素材、原生帧、旧交付与失败文件分别保存。

默认不把“未验收”“预览”“状态”等文字烧进视频，不新加水印，不用光流/叠化遮掩问题。质量说明写聊天；用户要对比才并排同步播放一条原音。原视频本来有文字/水印需另行获准处理，不冒称去除。

## 失败处理

- 认证失败：停止，不输出凭证、不猜刷新端点，让用户走官方认证。
- 提交超时：本地SUBMISSION_UNKNOWN和唯一slug保留。先status/网页查同任务；禁止删除标记重新submit或新prepare绕开。
- 节点缺失/模型hash错：应在下载/安装/生成前尽早失败。修输入后需新授权判断是否再消耗GPU，不循环重投。
- 显存/内存：先核对CUDA OOM、cgroup oom/oom_kill、CPU内存、进程退码与最新堆栈。内存接近上限不等于OOM；SIGSEGV不是自动归因OOM。
- 解码失败：保留latent/native输出若存在。修解码或本地封装，不默认重跑整个昂贵采样。
- 云端失败：在当前回合读取日志、提出可证伪原因、最小修复与回归；不要只发“失败”后悄悄结束，也不要无依据消耗第二轮额度。
- 取消：宿主定时任务关闭不等于云GPU停止。使用Kaggle准确任务的Stop Session；无精确会话ID时诚实说未确认，不猜ID调用取消，不删除Notebook制造不确定结果。

## 单次重试边界

网络只读可有界重试，远端提交永远不盲目重放。新运行保持独立UUID与sourcehash，明确修复了什么。额度不足时停止并报告，没有GPU自动切TPU或多账号轮换策略。
